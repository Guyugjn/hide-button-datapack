多人捉迷藏小游戏。每人拿到全套按钮却只能藏一个，**按到别人的按钮得分，而且按得越早分越高**。

两种模式，设置书里一键切换：

- **经典 · 各藏各找**：每人轮流藏一个按钮，藏完一起找；按钮被找完本轮结束。
- **轮流 · 一人藏众人找**：一轮只有一人藏，其余人抢着找；第一个找到的人分最高，
  藏得没人找到就由藏匿者把分收走；每个周期每人各藏一次。

可以设置多轮，分数跨轮累计，每轮结束播报完整名次。

## 下载

到 [Releases](../../releases/latest) 页面下载对应版本的 zip，**不要解压**，
直接放进存档的 `datapacks/` 文件夹即可。详见「装哪个包」一节。

> 仓库里不含构建产物。想自己构建或改代码，见「[开发者](#开发者)」。

## 一、装哪个包

数据包按 Minecraft 版本分成 3 份，**按服务端版本选一个装**（不需要都装）：

| 你的游戏版本 | 下载 | 按钮种类 |
|---|---|---|
| 1.16.2 – 1.20.4 | `ybih-1.16.2-1.20.4.zip` | 10 |
| 1.20.5 – 1.21.4 | `ybih-1.20.5-1.21.4.zip` | 13 |
| 1.21.5 – 26.2 | `ybih-1.21.5-26.2.zip` | 14 |

三个文件都在 [Releases](../../releases/latest) 里。

安装：把对应 zip **原样**复制到存档的 `saves/<世界名>/datapacks/` 下，进游戏执行 `/reload`。
看到聊天栏出现「数据包已加载」就是成功了。

> **不要解压**。游戏能直接读 zip，解压反而会把 `pack.mcmeta` 多套进一层目录里，导致读不到。

### 谁需要装

**只需要房主装一份，其他玩家什么都不用装。**

数据包是服务端逻辑（函数、进度、标签、记分板、实体都在服务端运行），客户端只负责渲染。
玩家连进来就能看到侧边栏、屏幕顶部的 Boss 栏倒计时，**不需要装数据包、不需要装模组、不需要 OP 权限**。

| 场景 | 数据包放在哪 |
|---|---|
| 单人存档开局域网给朋友玩 | `saves/<世界名>/datapacks/` |
| 专用服务器 | `<服务端目录>/world/datapacks/`，然后重启服务端或执行 `/reload` |
| Realms | 上传到 Realm 对应的世界里 |

两个注意点：

- **选哪个包看服务端版本，不是客户端版本**。服务端 1.21.5 就装 `ybih-1.21.5-26.2`，
  玩家的客户端版本更高也照样用这个包。
- **装完需要 `/reload` 或重启服务端才生效**，而 `/reload` 会清空对局数据。
  所以正确顺序是：先装包、再开房，别玩到一半才 reload。

## 二、开一局

### 1. 建议先开启死亡不掉落

数据包本身不碰游戏规则（为的是跨版本兼容），需要你自己开：

```mcfunction
/gamerule keepInventory true
```

### 2. 拿设置书

```mcfunction
/function ybih:admin/book
```

你会拿到一本「按钮游戏设置」书。**游戏里所有可调项都在这本书里，点带下划线的条目就能执行**
（灰色的是说明文字，点了没反应）。
每页最下面一行是页脚（`第 N / 12 页　目录`），点其中的「目录」直接回到第 1 页。

> **换过数据包之后一定要重新拿一本。** 书是普通物品，内容在拿到手的那一刻就固定了，
> 之后再改数据包它也不会跟着变 —— 所以「书里找不到新选项」几乎都是手里拿着旧书，
> 而不是数据包没生效。

### 3. 选模式与确认方式

还在书里（第 1 页是目录，每行写着「几页　这页讲什么」，点那一行直接跳页；
条目上**悬停能看到更详细的说明**）：

- 第 3 页【游戏模式】点「切到经典模式」或「切到轮流模式」（**对局进行中不能切换**）。
- 第 4 页【放错确认】默认**开启**：放下按钮后聊天栏会出现【确认】与【取消重放】，
  点【确认】才生效；放错位置就点【取消重放】，按钮收回去、材质退回来，可以换个地方重放。
  嫌麻烦可以关掉，改成放下即生效。

### 4. 设集合点

站到**集合点**（开局和搜寻期大家集合的地方，也是边界的中心），打开书点「集合点设在我脚下」。

点一下就设好了，位置会自动记录并强制加载该区块。**高空等待室**建在它正上方，
**活动边界**也以它为中心 —— 所以点位选好后，可以顺手在书里决定要不要开边界、开多大。

### 5. 开始游戏

```mcfunction
/function ybih:start
```

如果集合点还没设好，`start` 会提示并把设置书递给你，**不开局**。
只有你一个人时也能开局，只是会提示一句「搜寻阶段不会有人按按钮」。
（设点必须本人到现场，所以没法一条命令连设点带开局一起完成。）

## 三、玩法流程

一局由若干「轮」组成，每轮包含一次完整的「藏匿 → 搜寻」，分数跨轮累计。
经典模式的轮数就是书里的总轮数（默认 1）；轮流模式下书里填的是**周期数**，
一个周期每人各藏一次，所以一局至少有「人数 × 周期数」轮。

屏幕上方有一条 **Boss 栏**当总倒计时：标题写着「第几轮 · 现在是什么阶段 · 还剩多久」，
下面那根进度条按剩余比例收窄，颜色也跟着收紧——剩余过半是绿的，掉到两成以下变红。
物品栏上方只在**需要你动手**的时候才出现提示（例如「已放下 · 聊天栏点【确认】生效」），
搜寻阶段的冷热提示也在那里。

屏幕右侧是**分数榜**，按分数从高到低排。榜上只列**当前在线**的人：谁退出去，他那行立刻从榜上
消失，但成绩不会丢——分数记在存档里，重连回来照旧显示。

### 经典模式 · 各藏各找

1. **准备阶段**（默认 10 秒）：所有人被传到集合点。
2. **轮流藏匿**：按玩家顺序一个一个来。
   - 轮到你：你被传回集合点，**这时才会拿到全套按钮**，聊天栏提示「轮到你了」。
   - 没轮到的人：被送进集合点正上方的密闭等待室，看不到你藏在哪。
   - 你**只能藏一个按钮**。放下后聊天栏出现【确认】/【取消重放】，点【确认】生效，
     背包里其余按钮立刻全部消失，随即换下一位。
   - 每人限时（默认 60 秒）。超时没确认要**扣 1 分**，按钮被收回，本回合作废（你照样能去找别人的）。
3. **搜寻阶段**：所有人传回集合点，开始找。
   - 按到**别人**的按钮就得分：分数 = 此刻场上还剩几个按钮（含按下的这个）。
     4 人局就是 4 / 3 / 2 / 1，**手快的人拿得多**。
   - 按到**自己**的按钮：不得分，按钮保留。
   - 每 60 秒会提示你「半径 N 格内有/没有别人的按钮」，不告诉方向。**间隔和半径都能在书里调。**
4. **本轮结束**：全场按钮被找完，或者搜寻倒计时（默认 600 秒）归零。
   - **按钮没被找到的人各 +1 分**（藏得好也有回报），然后播报本轮完整名次。
   - **带全员围观**：本轮**每一个藏过按钮的人都展示一遍**，不管那个按钮有没有被找到，
     逐个传送过去看（见下）。
   - 还有轮次 → 清场、全员回集合点，直接进入下一轮（分数保留）。
   - 轮次用完 → 播报最终排名、**全员回到集合点**，结束整局。

### 轮流模式 · 一人藏众人找

1. **准备阶段**：所有人被传到集合点。
2. **藏匿阶段**：**只有一位玩家上场藏**（每轮换人，按玩家顺序轮）。
   - 藏的人：传回集合点，拿到全套按钮，藏一个并确认（同上，60 秒限时）。
   - 其他人：在等待室等着。
3. **搜寻阶段**：搜寻者传回集合点开找；**藏匿者转旁观模式观战**，可以看别人怎么找。
   - 按钮**不会消失**，所有搜寻者抢着找它，**按找到的先后顺序计分**：
     分数 = 此刻还有几个搜寻者没找到（含自己）。3 个搜寻者就是 3 / 2 / 1。
   - 每 60 秒的冷热提示对搜寻者照常生效。
4. **本轮结束**：所有搜寻者都找到，或者搜寻倒计时归零。
   - 剩下的「没人找到的那一份」归藏匿者：3 个搜寻者全找到 → 0 分，找到 2 个 → +1 分，一个都没找到 → +3 分。
   - **带全员围观**：藏匿者这一轮藏的按钮会被拿出来给所有人看一遍（见下）。
   - 然后换下一位藏：**判断依据是「这一周期里还有谁没藏过」**，所以每个人都一定会轮到，
     所有人都藏过一次算一个周期；书里填的周期数用完才收官。

> 得分口径统一是「**余量分**」：抢得越早，场上剩余份数越多，拿得越多。
> 一局下来分数天然拉开，名次基本不会并列；万一同分，按「发现次数 → 首次发现时间」排先后。

### 轮末围观

每轮结束时，**本局每一个藏过按钮的人都会被公开展示一遍**——不管那个按钮有没有被找到。

- **被找到的按钮会临时摆回去**：它在被按下那一刻就消失了，但位置、材质、朝向都还记着，
  展示到它时会照着原样重新放出来，看完再收掉。
- 全员自动切成**旁观模式**并给夜视，逐个传送过去，**每个停 10 秒**自动换下一个。
- **站位是按钮自己那一格**：视角按按钮贴在哪面自动对准——贴地的俯视、贴天花板的仰视、
  贴墙的正对那面墙。传送到位后头 **1 秒**位置会被定住（防止你手还按着方向键直接飞出去），
  但**视角始终可以自由转动**。
- **当前这个按钮会亮起轮廓光**，隔着方块也看得见，一眼就知道在看哪儿。
  **红色 = 已经被找到，绿色 = 还没被找到**；同时只有这一个亮，
  换到下一个时上一个立刻灭。藏这个按钮的人身上也会亮同一种颜色。
- 屏幕上方显示「**已被找到 / 没被找到**的按钮 · **谁藏的** · N / M · 还剩 N 秒」，
  也就是连名字一起报出来。**剩余秒数每秒往下掉、进度条同时往回缩**，
  物品栏上方同步显示同样的进度。最后一个也要停满 10 秒才收尾。
- 展示顺序是**先藏的先看**（按藏下的先后），不会来回绕远。
- 按钮藏得再远也不会漏：展示期间会把它们所在的区块临时钉住，免得传送一走就掉出加载范围。
- **可以在书里关掉**（「轮末围观」那一页）。关掉后轮末直接结算，不做任何传送。
- 看完按钮会被收走，世界恢复原样，玩家身上的轮廓光和队伍身份也一并清掉。
- 被保护机制收回的按钮（位置反复被水或爆炸冲毁）不在展示范围内。

**整局结束时全员回到集合点**，不管你之前蹲在哪个角落；按中止也一样。

## 四、命令表

| 命令 | 作用 |
|---|---|
| `/function ybih:start` | 开始游戏；集合点没设好时提示并拒绝开局，只有 1 人时给一句提示但照常开局 |
| `/function ybih:stop` | 中止当前对局（不发奖励、不播报排名） |
| `/function ybih:reset` | 清空全部对局数据（空闲状态才能用） |
| `/function ybih:admin/book` | 拿到管理员设置书（所有设置都在这本书里） |
| `/function ybih:config/mode_1` `mode_2` | 切换游戏模式（对局进行中不可用） |
| `/function ybih:config/confirm_on` `confirm_off` | 开关放错确认（对局进行中不可用） |
| `/function ybih:config/apply` | 重新套用配置项 |

**`/reload` 会清空对局数据、但保留设置与集合点**：场上按钮（含已放置的方块）与高空等待室
全部清除、玩家分数归零、游戏模式还原，而书里改过的时长、轮数以及集合点都还在。

中途进服的玩家在对局中自动转为旁观并带夜视。

## 五、可调配置

**推荐直接用设置书改**：打开书点带下划线的条目即可，游戏内就能调，不用碰文件。
书的条目覆盖：游戏模式、放错确认、集合点与活动边界、准备阶段时长、每人藏匿时长、搜寻时长、
提示间隔、总轮数、开始/中止/重置。

要让改动**永久生效**（换存档或重新加载后仍是新值），就改
`data/ybih/function/config/apply.mcfunction` 里的数字，然后 `/reload`。
（该文件只在首次加载时执行一次，所以直接 reload 不会覆盖你已经在书里改过的值。）

| 配置项 | 默认值 | 含义 |
|---|---|---|
| `#mode` | 1 | 游戏模式：**1 经典 / 2 轮流** |
| `#confirm` | 1 | 放错确认：**1 开启 / 2 关闭** |
| `#prep_time` | 10 | 准备阶段秒数 |
| `#hide_time` | 60 | 每人藏匿回合秒数 |
| `#search_time` | 600 | 搜寻期秒数（兜底，找完会提前结束） |
| `#hint_period` | 60 | 冷热提示间隔秒数 |
| `#hint_range` | 10 | 冷热提示的探测半径（格），书里六档 5 / 10 / 15 / 20 / 30 / 50 |
| `#protect_period` | 5 | 按钮保护检测间隔 tick |
| `#rounds` | 1 | **总轮数**；轮流模式下是**周期数**（一局至少有周期数 × 人数轮） |
| `#border_on` | 0 | 活动边界：**0 关闭 / 1 开启** |
| `#border_r` | 100 | 活动边界半径（格），书里九档 20 / 30 / 40 / 50 / 60 / 70 / 80 / 90 / 100 |

> **书里改过的设置会被保留**：`/reload` 只清对局数据（分数、场上按钮、高空等待室、玩家状态），
> 设置与集合点都还在。想恢复默认就执行 `/function ybih:config/apply`。

### 活动边界（可选）

以集合点为中心拉一圈世界边界，跑不出去，圈外也放不了、点不了按钮 —— 藏匿范围自然被限制住。
默认**关闭**。

**书里只是设定，边界要等开局才出现。** 在书里点「边界开」并选好半径（九档 20 / 30 / 40 / 50 /
60 / 70 / 80 / 90 / 100 格，或「跟随手动」），这些条目只记录设置、当场不会立起边界墙；
点【开始游戏】时才真正生效。反过来，**点「边界关」、`/reload`、打完整局、按中止、点重置都会
立刻把边界撤掉**，恢复原版状态。

- 世界边界是**写进存档的世界设置**，不像我们的按钮那样归数据包管。
  `/worldborder center` 只能设、不能读，所以中心一旦对到集合点就**回不到原位置**；
  想保底就在开局前备份 `saves/<世界名>/data/world_border.dat`。
- 想用九档之外的半径：先手动敲 `/worldborder set <半径 × 2>`（命令收的是边长，
  点书里的「跟随手动」会一并列出写法），再把半径选成「跟随手动」—— 这样开局只重新对中、不覆盖尺寸。
- 等待室建在集合点正上方，必定落在圈内，所以等待的人不受影响。
- **边界是物理屏障，玩家走不出去**；但保险给的抗性提升会把边界伤害一并免掉，
  拦住人的是那堵墙本身，不是掉血。
- 聊天栏最后一行显示的是「世界边界直径」**当前实际值**，可以用来确认设置到底生效没有。
- **最外一圈不许放按钮**：贴着墙那一格放下会被退回并提示，往里挪一格即可。
  世界边界的物理墙按整方块取整、墙所在那一格仍算圈内，所以要额外拦一道。

### 饥饿与免伤

**点开始游戏之后**，参与者会一直带着两份保险，**直到下一次 `/reload` 或点重置**：

- **不会受伤**：抗性提升 V（减免 100%），摔落、岩浆、火焰、溺水、怪物伤害全部免掉。
- **不会挨饿**：饱和 V 常驻，饥饿条始终是满的。

死亡本来会清空全部状态效果，这里靠「每秒重发一次 + 一死亡就立刻补」顶回来，
所以掉线、死亡、整局结束、按中止之后**都不会掉**。

代价有两个，都不影响玩法：饥饿值永远是满的，所以**吃不下任何食物**（包括金苹果）；
饱和会在状态栏常驻一个图标。

**虚空伤害和 `/kill` 免疫不了**，掉出世界照样会死。

### 高空等待室

没轮到的人在集合点正上方的一间石英房子里等（内空 9×9、3 格高），四面不透光，看不到藏匿者。
进去之后 Boss 栏倒计时照常显示，能看见还剩多久。

房子高度按版本走：**1.16.2–1.20.4 的包建在 y=245**，**1.20.5 以上的包建在 y=300**。
后者是因为 1.18 起世界长高了（可放置到 y=319）、自然地形最高能到 y=256，不抬高就会被山埋掉。

这间房子是数据包**真实砌出来的方块**：整局结束与 `/reload` 都会拆掉。
如果那个高度正好压着地图建筑会被覆盖 —— 在意的话先挪开建筑，或改
`src/manifest.mjs` 里对应包的 `waitRoomY`，然后重新构建。

## 七、已知限制

- **包 1 的 1.19/1.20 玩家、包 2 的 1.21.4 玩家会少几种按钮**（按钮取的是该包覆盖区间的下限）。
- **不要用 `/kill @e[type=armor_stand]` 这类命令清场**：按钮是靠隐形标记管理的，标记被清掉后那些按钮就失去管理了。要清场请用 `/function ybih:reset`。
- **归属判定现在要求「对着按钮的那个交互」**：进度事件只对按钮触发，而且会记下是哪一个按钮，
  判定时两边的按钮编号必须对得上。所以分数的归属跟着真正按下按钮的那个人走 ——
  旁边随手右键别的方块、隔墙开箱子都不会再把分抢走，也无法再被冒充。
- **按钮被箭、三叉戟或风弹点亮不算数**：那不是玩家按的，没有对应的交互事件，无人认领。
- **按下瞬间如果已经转头**，只要那次交互被进度捕获到，这次按下照样算数；
  万一射线没锁定到按钮（例如站在奇怪的角度），这一次会算漏，需要再按一次。
- **如果你把按钮私藏起来（比如塞进箱子）再在别人的回合放下**，那个按钮不会被注册、也不会被清场清掉。
- 如果服务器或插件禁用了聊天栏点击事件，【确认】/【取消重放】点不了：把书里第 4 页的【放错确认】关掉即可。
- **对局开始后再进服的玩家会转为旁观**，不并入本局轮换；想让他参与就重开一局（重连回来的玩家会恢复参与身份）。
- 书页排版按默认字体的宽度排（每页 14 行）；如果装了会改字体宽度的资源包，可能出现折行、页脚被往下挤。
- **1.16 / 1.16.1 不在支持范围内**（包 1 的起点是 1.16.2）。
  这两版的标签语法与本包不兼容，装上会出现按钮放不下去的情况，请升级到 1.16.2 以上。
- 数据包不生成地形，也不管理除按钮之外的地图方块。
- **活动边界是正方形、且只在主世界生效**（1.21.9 起每个维度各有自己的边界）。
  等待室建在集合点正上方，所以必定落在圈内；但**藏匿范围要你自己按半径规划**，
  半径太小会让玩家挤在一起。
- 保险给的抗性提升会**连边界伤害一并免掉**（跨界版本的确切行为尚未实测，见测试清单）。
  这不妨碍边界拦住人——拦住人的是那堵物理墙——只影响「出圈后会不会掉血」。
- 保险是直接覆盖式的：**玩家自己喝的抗性、饱和药水效果会被顶掉**，而且**死亡后会自动补回来**，
  所以对局中不必也不要去嗑药。
- **高空等待室会真实改动地图**：它按包建在 y=245 或 y=300，那一层的原有方块会被石英覆盖。
  在意的话先清空该高度，或改 `src/manifest.mjs` 里对应包的 `waitRoomY`。
- **轮末围观只作用于本局参与者**：他们会被切成旁观并一起传送看展示。
  围观期间进服或重连的人也会被一并纳入旁观与展示，结束时还原。地图里还有别人在玩别的，
  就把开局时间错开。
- **射线不判遮挡**：放置后系统沿视线最多找 4 格来定位刚放下的按钮。如果地图自带的装饰按钮
  恰好是同款材质、又正好落在视线上，它可能被误认成本次藏匿的按钮，之后被按下时会被清成空气。
  在意的话别在藏匿点附近摆同款按钮。
- **按钮被爆炸或活塞破坏时，保护机制会把它修回来**（最多 4 次，之后收回）。
  修复不掉落物品，破坏者拿不到任何好处；但按钮被收回后，物主在轮末拿不到「没被找到」那一分。
- 围观会把按钮**临时摆回世界里**看，包括已经被找到的、原本方块早就没了的那些，看完收掉。
  要是展示正卡在半途时关服或崩溃，这些按钮会留在世界里；下次进服 `/reload` 会自动清掉。
- 围观期间会**临时强制加载**那些待展示按钮所在的区块（否则传送一次就会把后面的按钮挤出
  加载范围、展示队列当场断掉），展示一结束就放开，`/reload`、重置、整局结束也都会放开。
  服主自己用 `/forceload` 加载过同一个区块的话，会被一并放开。
- 围观的高亮**用的是队伍颜色**，所以数据包会建两个内部队伍（`ybih_found` 红、
  `ybih_notfound` 绿）。它们只用来给展示标记和当前那位物主上色，**普通玩家不会留在队里**，
  围观一结束就退干净。你的地图要是自带队伍体系，注意别跟这两个名字撞上。
- **水会漫进来的位置放不了**：放下会**当场退回并提示**，按钮不会被消耗，换个地方就行。
  判据是按钮的**四个水平邻格加上方**有没有水（**不分水源与流水**）或岩浆 ——
  Java 版里按钮泡在水里存不住，水迟早漫进按钮格把它冲掉、并掉落一个按钮，反复下来就成了刷物品。
  **正下方是水不算**：水不向上流，桥面、水下天花板上那种位置照常能藏。
  **含水的方块（含水楼梯、含水栅栏那类）也不算**：里面的水是困住的，不会流出来。
  又贴边界又挨着水时只弹一条提示，不会两条一起冒出来。
  万一是放完之后水才流过来，那个按钮会被保护机制收回并通知物主（见下条）。

## 开发者

### 从源码构建

```bash
node tools/build.mjs
```

产物在 `dist/`：三个分版本 zip。脚本在打包前会做静态校验（JSON 合法性、函数引用、
命令语法、跨版本命令误用、白名单方块是否存在、书页排版等），**校验不通过就不会产出 zip**。

构建脚本不依赖第三方包，只需要 Node 18+。

```bash
python3 tools/verify_zips.py   # 校验产物的 CRC 与结构（可选）
```

### 项目结构

```
src/
├── manifest.mjs         三个包的定义、物品语法、文本 token（各版本差异的唯一来源）
├── book.mjs             设置书的文案与排版（行模型、页脚定位）
├── block_versions.mjs   方块 ID → 起始版本 对照表，白名单按它过滤
└── data/                数据包源码（函数、进度、标签）
tools/
├── build.mjs            构建 + 静态校验 + 手写 ZIP 打包
└── verify_zips.py       产物校验
dist/                    构建产物，不纳入版本管理
```

**只改 `src/`**。`dist/` 是生成物，下次构建会被覆盖。

### 为什么分成三个包

Minecraft 的跨版本语法断代无法用运行时判断绕过 —— Brigadier 在**解析期**就检查整行，
写错就是整个函数不加载。项目里共有四道硬边界：

| 分界 | 变化 |
|---|---|
| 1.20.5 | 物品 NBT → 数据组件（`CanPlaceOn:` → `can_place_on={...}`） |
| 1.21.5 | 文本 JSON → SNBT（`clickEvent` → `click_event`） |
| 1.21 | 目录改名（`functions/` → `function/`、`tags/blocks/` → `tags/block/`） |
| 1.20.5 / 1.21.5 | 隐藏「可放置在」提示行的组件换了三次 |

这些边界互不重合，所以三个包在 `src/manifest.mjs` 里各自声明区间，由构建脚本注入差异。
