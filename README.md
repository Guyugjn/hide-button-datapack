# 你的按钮我来藏

Minecraft Java 版数据包 · 命名空间 `ybih` · 支持 1.16.2 – 26.2

[![构建并发布](https://img.shields.io/github/actions/workflow/status/Guyugjn/hide-button-datapack/release.yml?label=%E6%9E%84%E5%BB%BA%E5%B9%B6%E5%8F%91%E5%B8%83&logo=github)](https://github.com/Guyugjn/hide-button-datapack/actions/workflows/release.yml)
[![许可证](https://img.shields.io/badge/license-MIT-blue.svg)](LICENSE)
[![Minecraft](https://img.shields.io/badge/Minecraft-1.16.2%20–%2026.2-green.svg)](#一装哪个包)

多人捉迷藏小游戏：**每人拿到全套按钮却只能藏一个，按到别人的按钮得分，按得越早分越高。**

- **经典 · 各藏各找** —— 每人轮流藏一个按钮，藏完一起找。
- **轮流 · 一人藏众人找** —— 一轮只有一人藏，其余人抢着找。

两种模式在设置书里一键切换。按钮**按一次不会消失**：每个按钮各带一份分
（初始 = 参与人数 − 1），谁按谁取走一份，分被拿光才收走；**每人每个按钮只算一次**。
分数跨轮累计，每轮结束播报完整名次。

## 一、装哪个包

数据包按 Minecraft 版本分成 3 份，**按服务端版本选一个装**（不需要都装）：

| 你的游戏版本 | 下载 | 按钮种类 |
|---|---|---|
| 1.16.2 – 1.20.4 | `ybih-1.16.2-1.20.4.zip` | 10 |
| 1.20.5 – 1.21.4 | `ybih-1.20.5-1.21.4.zip` | 13 |
| 1.21.5 – 26.2 | `ybih-1.21.5-26.2.zip` | 14 |

三个文件都在 [Releases](../../releases/latest) 里。

安装：把对应 zip **原样**复制到存档的 `saves/<世界名>/datapacks/` 下，进游戏执行 `/reload`。
看到聊天栏出现「数据包已加载」就是成功了。

> **不要解压。** 游戏能直接读 zip，解压反而会把 `pack.mcmeta` 多套进一层目录里，导致读不到。

### 谁需要装

**只需要房主装一份，其他玩家什么都不用装。**

数据包是服务端逻辑（函数、进度、标签、记分板、实体都在服务端跑），客户端只负责渲染。
玩家连进来就能看到侧边栏和屏幕顶部的倒计时，**不需要装数据包、不需要装模组、不需要 OP 权限**。

| 场景 | 数据包放在哪 |
|---|---|
| 单人存档开局域网给朋友玩 | `saves/<世界名>/datapacks/` |
| 专用服务器 | `<服务端目录>/world/datapacks/`，然后重启服务端或执行 `/reload` |
| Realms | 上传到 Realm 对应的世界里 |

两个注意点：

- **选哪个包看服务端版本，不是客户端版本。** 服务端 1.21.5 就装 `ybih-1.21.5-26.2`，
  玩家的客户端版本更高也照样用这个包。
- **装完需要 `/reload` 或重启服务端才生效，而 `/reload` 会清空对局数据。**
  所以正确顺序是：先装包、再开房，别玩到一半才 reload。

## 二、开一局

### 1. 建议先开启死亡不掉落

数据包本身不碰游戏规则（为的是跨版本兼容），需要你自己开：

```mcfunction
/gamerule keepInventory true
```

### 2. 拿设置书

```mcfunction
/function ybih:admin/book
```

你会拿到一本「按钮游戏设置」书，共 12 页。**游戏里所有可调项都在这本书里，
点带下划线的条目就能执行**（灰色的是说明文字，点了没反应）。
每页最后一行是页脚，点其中的「目录」直接回到第 1 页。

> **换过数据包之后一定要重新拿一本。** 书是普通物品，内容在拿到手的那一刻就固定了，
> 之后再改数据包它也不会跟着变 —— 所以「书里找不到新选项」几乎都是手里拿着旧书，
> 而不是数据包没生效。

### 3. 设集合点

站到**集合点**（开局和搜寻期大家集合的地方，也是边界的中心），打开书点「集合点设在我脚下」。

点一下就设好了，位置会自动记录并强制加载该区块。**高空等待室**建在它正上方，
**活动边界**也以它为中心 —— 所以点位选好后，可以顺手在书里决定要不要开边界、开多大。

### 4. 开始游戏

```mcfunction
/function ybih:start
```

如果集合点还没设好，`start` 会提示并把设置书递给你，**不开局**。
只有你一个人时也能开局，只是会提示一句「搜寻阶段不会有人按按钮」。
（设点必须本人到现场，所以没法一条命令连设点带开局一起完成。）

## 三、玩法流程

### 经典模式 · 各藏各找

1. **准备阶段**（默认 10 秒）：所有人被传到集合点。
2. **轮流藏匿**：按玩家顺序一个一个来。
   - 轮到你：你被传回集合点，**这时才会拿到全套按钮**，聊天栏提示「轮到你了」。
   - 没轮到的人：被送进集合点正上方的密闭等待室，看不到你藏在哪。
     等的时候不无聊：物品栏上方写着「正在藏匿：X · 剩 N 秒 · 你是第 K 位」，
     聊天栏里贴着一张**九宫格棋**名单：点谁后面的【邀请】就去找谁，对方点【同意】就开局，
     两人各自在聊天栏点格子下棋，**能同时开几局只看房里有多少人**。
   - 你**只能藏一个按钮**。放下后聊天栏出现【确认】/【取消重放】，点【确认】生效，
     背包里其余按钮立刻全部消失，随即换下一位。
   - 放在**半砖、楼梯、活板门**这类不完整方块旁边也没问题 —— 数据包会认准你**刚放下的那一格**，
     不会把标记错认到旁边的旧按钮上。
   - 如果背包满了装不下全部按钮，会明确提示你「多出来的已经掉在脚边」，捡起来就能接着藏。
   - 每人限时（默认 60 秒）。超时没确认要**扣 1 分**，按钮被收回，本回合作废（你照样能去找别人的）。
3. **搜寻阶段**：所有人传回集合点，开始找。
   - **场上的按钮都带着分，一个个按过去**：每个按钮初始 = 参与人数 − 1 分。
     6 人局就是 5 分，按到的第一个人 +5、第二个 +4、第三个 +3，一路递减。
   - **按钮不会因为被按过就消失**，它只是少一分；分被拿光才收走。
     所以每个按钮人人都能按一次，**手快的人拿得多**。
   - **每人对每个按钮只算一次**：重复按同一个按钮不得分，会提示你按过了。
   - 按到**自己**的按钮：不得分，按钮保留。
   - 每 60 秒会提示你「半径 N 格内有/没有别人的按钮」，不告诉方向。**间隔和半径都能在书里调。**
4. **本轮结束**：所有按钮的分都被拿完（每位搜寻者都取过一份），或者搜寻倒计时（默认 600 秒）归零。
   - 播报本轮完整名次。
   - **带全员围观**：本轮**每一个藏过按钮的人都展示一遍**，不管那个按钮的分有没有被拿完，
     逐个传送过去看。
   - 还有轮次 → 清场、全员回集合点，直接进入下一轮（分数保留）。
   - 轮次用完 → 播报最终排名、**全员回到集合点**，结束整局。

### 轮流模式 · 一人藏众人找

1. **准备阶段**：所有人被传到集合点。
2. **藏匿阶段**：**只有一位玩家上场藏**（每轮换人，按玩家顺序轮）。
   - 藏的人：传回集合点，拿到全套按钮，藏一个并确认（同上，60 秒限时）。
   - 其他人：在等待室等着（可看信息栏、可与旁边的人对下九宫格棋）。
3. **搜寻阶段**：搜寻者传回集合点开找；**藏匿者转旁观模式观战**，可以看别人怎么找。
   - 场上只有这一个按钮，它带着 **参与人数 − 1** 分，**按到的第一个人分最高**：
     6 人局就是 5 分，依次 5 / 4 / 3 / 2 / 1。
   - **每人只能从这个按钮上拿一次**，重复按不得分。
   - 每 60 秒的冷热提示对搜寻者照常生效。
4. **本轮结束**：所有搜寻者都拿到分了（按钮的分被分完），或者搜寻倒计时归零。
   - **带全员围观**：藏匿者这一轮藏的按钮会被拿出来给所有人看一遍。
   - 然后换下一位藏：**判断依据是「这一周期里还有谁没藏过」**，所以每个人都一定会轮到，
     所有人都藏过一次算一个周期；书里填的周期数用完才收官。

> 得分口径统一是「**按钮分**」：每个按钮各带一份固定的分，谁按谁取走一份，取完一份它就少一分。
> 抢得越早，轮到你的那份越多。一局下来分数天然拉开，名次基本不会并列；
> 万一同分，按「发现次数 → 首次发现时间」排先后。

## 四、设置书里能调什么

一本书搞定全部设置，**改完立刻生效**（除标注「对局中不可用」的几项）。

| 页 | 能调什么 | 默认 | 可选档位 |
|---|---|---|---|
| 2 | 查看当前设置、开始 / 中止 / 重置 | — | — |
| 3 | 游戏模式：经典 / 轮流 | 经典 | 两种（**对局中不可改**） |
| 4 | 放错要不要再点一次【确认】 | 开启确认 | 开 / 关（**对局中不可改**） |
| 5 | 集合点；活动边界开关与半径 | 边界关 | 半径 20–100 每 10 一档，另有「跟随手动」 |
| 6 | 开局准备倒计时 | 10 秒 | 5 / 10 / 20 / 30 秒 |
| 7 | 单人藏匿时限 | 60 秒 | 20 / 30 / 45 / 60 / 90 / 120 秒 |
| 8 | 搜寻阶段时长上限 | 600 秒 | 180 / 300 / 450 / 600 / 900 秒 |
| 9 | 冷热提示的间隔与半径 | 间隔 60 秒、半径 10 格 | 间隔 15 / 30 / 60 / 120 秒，也可关闭 |
| 10 | 轮末围观开 / 关 | 开 | 开 / 关 |
| 11 | 总轮数（轮流模式下是周期数） | 1 轮 | 1 / 2 / 3 / 5 / 8 轮 |
| 12 | 规则与计分说明 | — | 只有文字，不可点 |

- **拿书用 `/function ybih:admin/book`**；换过数据包要重新拿一本（见上一节）。
- **轮流模式下第 11 页填的是「周期数」**，一局总轮数 = 周期数 × 参与人数。
- 「冷热提示」只告诉你**半径内有/没有**别人的按钮，**不告诉方向**；关掉后半径设置会留着。
- 边界是「设置与生效分离」：书里点「边界开」只记下设置，**开局时才真正出现那圈边界**；
  点「边界关」会**立刻**撤掉。

## 五、命令表

| 命令 | 作用 |
|---|---|
| `/function ybih:start` | 开始游戏；集合点没设好时提示并拒绝开局，只有 1 人时给一句提示但照常开局 |
| `/function ybih:stop` | 中止当前对局（不发奖励、不播报排名） |
| `/function ybih:reset` | 清空全部对局数据（空闲状态才能用） |
| `/function ybih:admin/book` | 拿到管理员设置书（所有设置都在这本书里） |
| `/function ybih:config/mode_1` `mode_2` | 切换游戏模式（对局进行中不可用） |
| `/function ybih:config/confirm_on` `confirm_off` | 开关放错确认（对局进行中不可用） |
| `/function ybih:config/apply` | 重新套用配置项 |

### `/reload` 会清掉什么、留下什么

| | 内容 |
|---|---|
| **清掉** | 场上按钮（含已放置的方块）、高空等待室、玩家分数与编号、临时状态 |
| **保留** | 书里改过的各项设置、集合点位置 |

**围观播到一半时 `/reload` 也能清干净**：围观期间按钮方块是被放回世界里摆着看的，
`/reload` 会连这些一起收掉，不会留下没人管的按钮方块。
展示中途 `/function ybih:reset` 与 `/function ybih:stop` 同理。

### 玩家游戏模式（冒险 / 生存 / 创造 / 旁观）：节点强制，其余自由

> 注意与第 3 页的「游戏模式：经典 / 轮流」区分 —— 那是**玩法**，这里说的是**玩家自身的
> 冒险 / 生存 / 创造 / 旁观**。

**参与者在对局中可以自己换游戏模式**（用 `/gamemode`），数据包不回收也不纠正。
只有这六个关键节点会强制切一次：

| 节点 | 切成 |
|---|---|
| 开局入队 | 冒险 |
| 轮到你藏 | 冒险 |
| 进入搜寻 | 参与者一律冒险（轮流模式的藏匿者随后转旁观观战） |
| 轮末围观 | 全员旁观 |
| 死亡重生 | 冒险 |
| 轮末 | 按入队时记下的原模式还原 |

- **为什么「轮到你藏」和「进入搜寻」也要按回冒险**：旁观模式放不下按钮、也按不了按钮。
  这两处若不按回来，当事人会什么都做不了，然后被超时判定白扣一分而看不出原因。
  这两处切换会给他一句说明。
- **代价请知悉**：节点之间切到**旁观**能穿墙、切到**创造**能飞，而等待室是靠四面密闭
  来防偷看的、搜寻阶段是靠按钮藏得好不好来分胜负的。所以在等待室里切旁观可以飞出去
  看别人藏在哪，在搜寻阶段切旁观可以直接穿墙找到所有按钮。
  **这一版有意把这个自由交给玩家**，请按自己的联机环境决定要不要这样玩；
  若要收紧，改 `player/active_state` 把模式强推加回去即可。
- **等待室的九宫格棋**在旁观模式下也能点（聊天栏点击不受游戏模式影响）。

### 掉线与中途加入

中途进服的玩家在对局中**自动转为旁观一次**、传送到集合点并带夜视；
他此后自己切回生存模式就不再干预（凭据 `ybih_spec_once` 记着「已接管过」）。
收尾时按入队前记下的原游戏模式还原；还原后若他仍未切回旁观，下一轮开始时会照常被并入对局。

夜视给的是有限时长、每秒顶上，凭据一旦回收、或他不再是旁观，一秒内连效果一起收掉 ——
不会在存档里留下跨局、跨 `/reload`、跨重连一直挂着的效果。
轮流模式下藏匿者在搜寻阶段的那份观战夜视同理；整局结束时掉线的人也不会被落下。

## 六、常见问题

**装了没反应？**
依次检查：① zip **没有解压**、直接在 `datapacks/` 下；② 装的包和服务端版本对得上；
③ 执行过 `/reload`；④ 聊天栏有没有「数据包已加载」。
`/datapack list` 能看到这个包才算装上了。

**书里找不到某个选项？**
手里那本是旧书。书的内容在拿到手时就固定了，**重新执行 `/function ybih:admin/book` 拿一本**。

**开局被拒绝，说集合点没设？**
站到想要的位置，打开书点「集合点设在我脚下」，再 `/function ybih:start`。

**某个按钮按了没加分？**
先看聊天栏的提示，每种情况都会明说：

| 提示 | 原因 |
|---|---|
| 你已经从这个按钮上拿过分了 | 每人每个按钮只算一次 |
| 这个按钮的分已经被拿完了 | 分被前面的人取光了 |
| 这个按钮已经不在了，本次不算 | 按钮刚被拿走 |
| 这是你自己的按钮，不算分 | 自己的按钮不给分，按钮保留 |
| 这次按下没算数：没能在视线方向上锁定到按钮标记 | 视线没锁到按钮 —— 站近一点、正对着它按 |
| 参与人数超出记录上限，这次点击没有计分 | 超过 30 人，见「已知限制」 |

**放在半砖 / 楼梯旁边，会不会认错按钮？**
不会。数据包认的是你**刚放下的那一格**，不会把标记落到旁边的旧按钮上。

**背包满了会怎样？**
会明确提示「你的背包放不下全部按钮，多出来的已经掉在脚边」，掉落物就在你脚下，
捡起来继续藏。发按钮前数据包会先清掉你身上上一轮残留的按钮，所以手上不会越攒越多。

**能中途改规则吗？**
模式和确认开关对局中不可改（点它会提示），其余（时长、轮数、提示间隔、围观开关）
随时可改，改完立刻生效。

**玩到一半有人掉线了？**
轮到他藏时按「没放按钮」处理并扣 1 分，这份欠账会挂到他编号上，**他重连时自动结清**；
分数与已拿过的分也都还在。

**怎么清场重来？**
`/function ybih:reset`。**只有空闲状态能用** —— 对局进行中执行会提示你先 `/function ybih:stop`。
**不要用 `/kill @e[type=armor_stand]`**，见下一节。

## 七、已知限制

- **包 1 的 1.19/1.20 玩家、包 2 的 1.21.4 玩家会少几种按钮**（按钮取的是该包覆盖区间的下限）。
- **不要用 `/kill @e[type=armor_stand]` 这类命令清场**：按钮是靠隐形标记管理的，
  标记被清掉后那些按钮就失去管理了。要清场请用 `/function ybih:reset`。
- **地图自带的按钮不会被本数据包管理**：地图原有按钮既不计分、也不参与判定，
  本数据包也不会去动它们。唯一要留意的是**别把自己的按钮紧贴在旧按钮上** ——
  虽然现在会认准你刚放下的那一格，但两个按钮挤在同一格附近时，你自己点起来也容易点错。
- **高空等待室会真实改动地图**：它按包建在 y=245 或 y=300，从**基准层下面一格**起、
  向上一共 6 层（基准层下面那层是地板的地基），这个范围内的原有方块会被覆盖。
  在意的话先清空该高度，或改 `src/manifest.mjs` 里对应包的 `waitRoomY`。
  等待室不是空地：里面有地毯、长椅、书架、天窗与盆栽，等待的人能看信息栏、能与旁边的人对下九宫格棋。
- **最多支持 30 名参与者参与计分**。去重用的是按钮上的位图（位号 = 玩家编号 − 1），
  32 位整数放不下更多；编号超过 30 的人按按钮会得到「参与人数超出记录上限，这次点击没有计分」。
  玩是可以玩的（他照样藏、照样找），只是**拿不到分**。
- **需要自己开 `/gamerule keepInventory true`**：数据包不碰游戏规则，为的是跨版本兼容。
  没开的话，搜寻阶段死一次会掉光背包，而冒险模式下玩家挖不了东西、捡不回来。

## 开发者

### 从源码构建

```bash
node tools/build.mjs
```

产物在 `dist/`：三个分版本 zip。脚本在打包前会做静态校验（JSON 合法性、函数引用、
命令语法、跨版本命令误用、白名单方块是否存在、书页排版等），**校验不通过的包不会产出
zip，并且会把它上一次留下的同名旧 zip 一并删掉** —— 只删暂存目录的话，`dist/` 里会混着
「本次成功的新包」和「上一次成功的旧包」，人工扫一眼会以为三个包都构建成功了。
不管哪种失败，退出码都是 1，**部署前请确认退出码**。

构建脚本不依赖第三方包，只需要 Node 18+。

```bash
python3 tools/verify_zips.py   # 校验产物的 CRC 与结构（可选）
node tools/check_md.js         # 检查文档格式（可选）
```

`tools/verify_zips.py` 只做 CRC 与结构检查，看不出内容新旧，所以它另外会比对产物与
`src/` 的时间戳，产物比源文件旧就报警。

### 项目结构

```
src/
├── manifest.mjs         三个包的定义、物品语法、文本 token（各版本差异的唯一来源）
├── book.mjs             设置书的文案与排版（行模型、页脚定位）
├── block_versions.mjs   方块 ID → 起始版本 对照表，白名单按它过滤
└── data/                数据包源码（函数、进度、标签）
tools/
├── build.mjs            构建 + 静态校验 + 手写 ZIP 打包
├── verify_zips.py       产物校验
└── check_md.js          文档格式检查
dist/                    构建产物，不纳入版本管理
```

**只改 `src/`。** `dist/` 是生成物，下次构建会被覆盖。

几个函数**不在 `src/` 里**，由构建脚本生成（改它们要去 `tools/build.mjs` 的 `GENERATED` 表）：
`player/give_buttons`、`button/tag_material`、`button/tag_face`、`button/press_tick`、
`button/press_scan`、`button/hit_bit`、`button/protect_check` / `protect_scan` / `protect_restore`、
`button/refund_pending`、`util/clear_placed_blocks`、`game/bar_value`、
`game/showcase_view`、`game/showcase_pin`、`game/hint_scan`、`admin/book`，
以及 `config/` 下的数值选项函数。

> **一个容易踩的坑**：`src/data/ybih/function/button/fluid_check.mcfunction` **在 `src/` 下确实存在**，
> 但它的内容是空的（只有两行注释），真正的内容由 `tools/build.mjs` 的 `genFluidCheck` 生成 ——
> 构建时 `if (GENERATED[rel]) continue` 会**跳过 src 那份**，所以改这个 src 文件**没有效果**
> （改了不报错、也不生效）。要改流体判据请改 `genFluidCheck` 与它上面的 `FLUID_NEIGHBORS`。
>
> 对照：`src/data/ybih/tags/block/placeable_surfaces.json` 是**真的源文件** ——
> `genPlaceableSurfaces` 把它读进来当输入、按各包版本下限过滤后再写出去。
> 想加可放置方块就往这个 src 文件里加，构建会自己按版本筛。

### 为什么分成三个包

Minecraft 的跨版本语法断代无法用运行时判断绕过 —— Brigadier 在**解析期**就检查整行，
写错就是整个函数不加载（而且函数加载失败**只写进日志、不进聊天栏**，表现成「什么都没发生」）。
项目里共有四道硬边界：

| 分界 | 变化 |
|---|---|
| 1.20.5 | 物品 NBT → 数据组件（`CanPlaceOn:` → `can_place_on={...}`） |
| 1.21.5 | 文本 JSON → SNBT（`clickEvent` → `click_event`） |
| 1.21 | 目录改名（`functions/` → `function/`、`tags/blocks/` → `tags/block/`） |
| 1.20.5 / 1.21.5 | 隐藏「可放置在」提示行的组件换了三次 |

这些边界互不重合，所以三个包在 `src/manifest.mjs` 里各自声明区间，由构建脚本注入差异。
